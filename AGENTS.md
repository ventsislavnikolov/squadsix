# Squad Six

Picks fair 6-a-side teams for the office game: the admin keeps the roster,
players sign up for an announced game (or someone picks the twelve on the
spot), Jev proposes three splits, the twelve vote, and the admin locks the
game and enters the result. Bilingual (Bulgarian by default, English). It runs
on Vercel. Domain words and product decisions: `CONTEXT.md`.

## Stack

- TanStack Start (Router and server functions, Nitro on Vercel), React 19,
  TypeScript, TanStack Query and Form, Tailwind CSS 4, shadcn/ui
  (`radix-rhea` preset).
- Neon Postgres over HTTP (`@neondatabase/serverless`), plain SQL in
  `src/server/repo.ts`; validation with Zod.
- Jev (a decision model) through OpenRouter with TanStack AI
  (`src/server/jev-harness.ts`); without `OPENROUTER_API_KEY` the teams are
  picked by arithmetic alone.
- Link-preview pictures rendered with satori and resvg (`src/routes/og.$id.tsx`).
- Vitest (jsdom and Testing Library for components) for unit tests; Biome
  through ultracite for lint and format.

## Layout

- `src/routes/`: pages (file routes; `src/routeTree.gen.ts` is generated by
  the router plugin, never edit it), `admin/` for the admin pages.
- `src/domain/`: pure logic (balancing, names, rules, sign-up order), with
  its tests beside it.
- `src/server/`: server functions (`functions.ts`), queries (`repo.ts`),
  admin session, activity log, the Jev harness, geocoding. Server-only: pages
  and components call `functions.ts` and import only types from the rest (the
  `og.$id.tsx` server handler is the one exception).
- `src/lib/`: client helpers (i18n, queries, weather, share, previews).
- `src/components/`: UI; `ui/` holds the shadcn primitives.
- `db/`: `schema.sql`, numbered migrations and a placeholder `seed.sql`.
- `test/`: shared test fakes (every server function as a `vi.fn`, a recording
  `sql`), `render-app.tsx` (the real route tree at a path) and fixtures.
- `scripts/`: `migrate.mjs` (apply a SQL file), `hash-password.mjs` (admin
  password hash), `install-git-hooks.mjs` (lefthook on `pnpm install`).

## Commands

Use pnpm. Node comes from `.nvmrc`.

- `pnpm dev`: dev server on port 3000 (reads `.env.local`).
- `pnpm lint` / `pnpm fix`: ultracite (Biome) check / auto-fix.
- `pnpm typecheck`: `tsc --noEmit`.
- `pnpm test`: Vitest once with coverage; fails below 90% lines, statements,
  branches or functions. `pnpm test:watch` watches, without coverage.
- `pnpm build`: production build.
- `pnpm ci:local`: lint, typecheck and test, fail-fast, as CI runs them.
- `pnpm env:pull` / `pnpm env:push`: sync `.env.vault` with dotenv-vault.
- `DATABASE_URL=… node scripts/migrate.mjs db/<file>.sql`: apply a migration.

Git hooks (lefthook): pre-commit runs Biome on staged files (check only),
commit-msg runs commitlint, pre-push runs `pnpm ci:local`. CI runs lint,
typecheck and test on every pull request and every push to `main`.

## Rules

- Biome via ultracite is the only linter and formatter; do not add ESLint or
  Prettier.
- Coverage stays at 90% or more on all four metrics (`vitest.config.ts`). It
  measures every file under `src/`, except the shadcn primitives in
  `components/ui/` and the generated route tree. Component tests start with
  `// @vitest-environment jsdom`; no coverage-ignore comments.
- Tests never reach Neon, OpenRouter or a weather API: mock `@/server/db`
  (`sql`), the AI adapter and `fetch`, as the existing tests do.
- Ratings, rules and Jev's trace are admin-only. `repo.ts` drops ratings for
  everyone else; rules are never shown or hinted at outside the admin pages
  (`CONTEXT.md`, "Rules").
- There is no scheduler: time-based steps run when someone opens the app
  (`repo.dueNow`). Keep them idempotent.
- The database is `db/schema.sql` plus the numbered migrations after it,
  applied in order by hand with `scripts/migrate.mjs`. A schema change is a
  new numbered file; keep every statement idempotent (`if not exists`).
- User-facing text lives in `src/lib/i18n.ts`, in both languages.

## Workflow

- Branch from `main` as `<type>/<topic>` (e.g. `fix/remember-me`).
- Conventional commits, `<type>(<scope>): <subject>`, imperative, at most 50
  characters; a gitmoji may lead (`✨ feat: …`). commitlint enforces the
  format (`commitlint.config.mjs`, `commit-format.mjs`).
- Open PRs with `.github/pull_request_template.md`, filling every section.
- Release: semantic-release on every push to `main` (`release.config.mjs`,
  `.github/workflows/release.yml`); `feat` minor, `fix` and `perf` patch,
  breaking changes major. It commits `CHANGELOG.md`, which Vercel skips.
- Vercel builds every pull request and deploys `main` to production.
- Env vars live in Vercel and `.env.vault`; local values go in `.env.local`
  (names in `.env.example`).

## Agent commands

Global Claude Code commands (defined in `~/.claude/commands`, not in this repo):

- `/create-commit`: conventional commits split by concern; the git hooks always run.
- `/create-pull-request`: push, open a PR from `.github/pull_request_template.md`, watch CI.
- `/cleanup`: check out main, pull, delete merged branches and their worktrees.
